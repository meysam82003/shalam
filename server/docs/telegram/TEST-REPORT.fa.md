# گزارش آزمون — بسته قابل نصب rc3

آخرین نسخه کد آزموده‌شده: `3af554413b5b6f2a97dd00eea35e38acdf267fc8`. [اجرای CI 39076550749](https://github.com/meysam82003/shalam/actions/runs/39076550749) با **۶۰۳ بررسی Backend روی MySQL 8، ۷۴ بررسی واسط و ۴۹ بررسی مرورگر** موفق شد؛ مجموع **۷۲۶ بررسی**. تصاویر گزارش موبایل و چاپ با داده مصنوعی بازبینی شدند. تاریخچه نسخه‌های قبلی در ادامه است. این نتایج، تأیید عملکرد نصب روی هاست اصلی یا اتصال واقعی تلگرام نیستند.

## نتایج تأییدشده در محیط محلی

- PHP 8.3 و MariaDB واقعی، دیتابیس مصنوعی جدا: ۵۶۹ بررسی موفق در مجموعه Backend اصلی + Telegram.
- امضای initData، پارامتر تکراری/دست‌کاری، تاریخ آینده/انقضا، replay، اتصال یک‌باره مقید به شناسه، جلوگیری از ورود کاربر عادی.
- ماتریس شش نقش، سقف نقش وب، لغو فوری نشست، تمدید بی‌صدای نشست فعال بدون رمز/کد، محدودیت نرخ و عملیات idempotent.
- رویداد واقعی ثبت‌نام و خرید با verifier آزمایشی؛ rollback مشترک، جلوگیری از paid جعلی و refund دستی، محاسبه درآمد بدون دوباره‌شماری.
- خرید/امضای بازار و مایکت، واسط ایران و درگاه‌های زرین‌پال/بلوپال/آبان در تست‌های موجود با پاسخ آزمایشی. برداشت پول یا استعلام خصوصی Production انجام نشد.
- صف: ارسال یک‌باره، پاسخ 429، محدودیت تلاش، timeout مبهم، worker قطع‌شده، لغو دسترسی پیش از ارسال، جلوگیری از افشای خلاصه پس از کاهش مجوز، سکوت و خلاصه شخصی.
- رسانه واقعی PNG، MIME اجرایی جعلی، جایگاه/فرمت ناسازگار، لینک XSS، تاریخ و سقف نامعتبر؛ جلوگیری از حذف رسانه متصل به اعلان.
- تیکت، یادداشت داخلی، گزارش‌های خواندنی، عدم خروج password/recovery/token/raw secrets، SEO روی فایل آزمایشی و محافظت مسیر.
- مهاجرت تکرارپذیر، حفظ داده، بکاپ و restore، تست‌های اصلی API/دستگاه/کد تخفیف.

## اصلاح کشف‌شده در CI

MySQL 8 با ONLY_FULL_GROUP_BY در نمودار وضعیت دوره‌ها خطا نشان داد؛ عبارت گروه‌بندی به subquery با ستون مشتق تغییر کرد تا در حالت سخت‌گیر نیز معتبر باشد. تکرار CI روی MySQL 8 با حالت سخت‌گیر با موفقیت گذشت. ۷۴ بررسی مستقل واسط پرداخت نیز محلی موفق شد.

## آزمون مرورگر و build

Chrome محلی به علت محدودیت سوکت سیستم اجرا نشد؛ همان آزمون در GitHub Actions اجرا شد و **۴۰ بررسی مرورگر موفق** ثبت شد. نسخه تست‌شده `cd362fd4c21d80398322ae7d5996d2c2371c1b61`، اجرای [39072924944](https://github.com/meysam82003/shalam/actions/runs/39072924944): **۵۷۰ بررسی Backend با MySQL 8، ۷۴ بررسی واسط و ۴۰ بررسی Playwright موفق**. داشبورد موبایل و ۲۲ بخش اصلی، عملیات یادداشت/تبلیغ/تیکت/ترجیحات، حالت روشن/تاریک، تبلت، قطع شبکه، CSV، رد origin جعلی و webhook بدون secret پوشش داده شدند. آپلود واقعی multipart، نمایش فایل ذخیره‌شده، ساخت اعلان با رسانه و جست‌وجوی سراسری نیز موفق شدند. تصاویر موبایل روشن/تاریک و تبلت بازبینی شدند؛ داده تصاویر فقط fixture مصنوعی است. کد قابل نصب این بسته با commit آزموده‌شده یکسان است؛ تغییر بعدی فقط به‌روزرسانی گزارش نتایج است.

کد Android تغییر نکرده است. gate الزامی AGENTS، یعنی `gradle --no-daemon testReleaseUnitTest assembleRelease`، ساخت APK با کلید انتشار و **Verify release signature** در [اجرای 39072292085](https://github.com/meysam82003/shalam/actions/runs/39072292085) با موفقیت گذشت. انتشار Release و سایت در این اجرای PR انجام نشد. منابع Android از commit آزموده‌شده تا نسخه بسته تغییر نکرده‌اند.

## موارد در انتظار آزمون واقعی

هاست اصلی و DB زنده، نسخه PHP سرور، Telegram API از شبکه هاست، webhook واقعی، Telegram Android/iOS/Web، عملکرد موبایل اقتصادی و دانلود CSV داخل webview واقعی تأیید نشده‌اند. Native SDK تلگرام در تست مرورگر با initData امضاشده آزمایشی جایگزین می‌شود؛ احراز هویت PHP واقعی است.

## اجرای دوباره

فقط با DB خالی/آزمایشی اجرا کنید؛ اسکریپت‌های تست جدول‌های با پیشوند `dvt_` و `dvtui_` را حذف و دوباره می‌سازند. این رفتار در تست است؛ migration بسته نصب حذف ندارد.

```sh
DIVAN_TEST_DSN='host=127.0.0.1;port=3306;dbname=divan_test2' DIVAN_TEST_USER=divan_test DIVAN_TEST_PASS='TEST_DB_PASSWORD' php server/tests/run.php
php payment-bridge/divan-bridge/tests/run.php
npm install --no-save --package-lock=false playwright@1.58.2
npx playwright install chromium
DIVAN_TEST_DSN='host=127.0.0.1;port=3306;dbname=divan_test2' DIVAN_TEST_USER=divan_test DIVAN_TEST_PASS='TEST_DB_PASSWORD' python3 server/tests/run-browser-local.py
```

مرورگر فقط روی توسعه/CI لازم است؛ هاست تولید به Node یا Playwright نیاز ندارد. تنظیمات، داده مصنوعی و کلید تست در ZIP تولید قرار نمی‌گیرند. آزمون‌ها و CI از سورس قابل اجرا هستند.

## کنترل بسته

ساخت ZIP فقط از فایل‌های سورس رهگیری‌شده انجام شد؛ config، کلیدها، رسانه‌های کاربر و داده DB وارد بسته نمی‌شوند. CRC و SHA-256 فایل‌ها، نبود کلید/config، وجود .htaccessها و SQL افزایشی بدون DROP/DELETE/ALTER کنترل شد. نصب واقعی cPanel انجام نشده است.
