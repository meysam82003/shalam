# راهنمای نصب مرکز مدیریت تلگرام — نسخه آزمایشی 1.0.0-rc2

این بسته برای بررسی و نصب روی staging است. سورس مبنا `main@ac784013c9a81d09b4c83dbe301cb4ed6398beaf` (۵.۵.۱) است؛ نسخه و تنظیمات سرور اصلی تأیید نشده‌اند. نصب روی Production در این مأموریت انجام نشده است.

## محتویات

- `divan/`: Backend کامل مبنا به‌همراه تلگرام؛ قابل نصب با نصب‌کننده موجود cPanel.
- `docs/`: ماتریس، معماری، راهنمای کار، وضعیت تست و بازگشت.
- `migration-12.sql`: SQL افزایشی اختیاری با پیشوند پیش‌فرض `dv_`؛ نصب عادی خودش migration را اجرا می‌کند.
- `SHA256SUMS.txt`: صحت فایل‌های داخل بسته.
- `source-changes.patch`: تغییرات توسعه برای بازبینی نسبت به commit مبنا؛ روی هاست اجرا نمی‌شود.

این بسته هیچ config، Bot Token، کلید امضای Pro، فایل کاربر یا داده واقعی ندارد. پوشه `site/`، APK و نسخه‌های دانلود در آن نیستند. پوشه‌های `app` و `storage` باید با قواعد .htaccess از وب مسدود بمانند. ZIP را پس از استخراج از public_html حذف کنید؛ مستندات و SQL را بیرون webroot نگه دارید.

## قبل از ارتقای نصب موجود

۱. در File Manager از کل `/public_html/divan/` (شامل config و کلیدها) و فایل‌های قابل ویرایش سایت نسخه پشتیبان بگیرید؛ از phpMyAdmin خروجی کامل DB بگیرید. فایل کلیدهای Pro را تغییر ندهید.
۲. در staging یک کپی مستقل بسازید. برای داده آزمایشی از DB خالی/مصنوعی استفاده کنید. اگر کپی DB لازم است، مقصدها و داده شخصی را محدود کنید. تلگرام به‌صورت پیش‌فرض خاموش است، ولی تنظیمات کپی‌شده ممکن است فعال باشند؛ قبل از اتصال شبکه آن‌ها را از پنل خاموش کنید.
۳. نسخه نصب‌شده، migrationهای ۱ تا ۱۱، مسیر base_url، نسخه PHP و تفاوت‌های فایل‌های هاست با مبنا را بررسی کنید. این بسته نباید تغییرات اختصاصی جدیدتر هاست را بازنویسی کند. اگر متفاوت‌اند، patch را با سورس همان سرور ادغام کنید.
۴. در بازه ارتقا، ورودی مدیریتی/ثبت خرید را موقتاً در لایه هاست متوقف کنید تا درخواست هم‌زمان حین جایگزینی فایل‌ها و migration وجود نداشته باشد. پوشه موجود را حذف نکنید؛ فایل‌های بسته را روی آن جایگزین کنید. `storage/config.php`، `storage/install.lock`، `storage/keys/`، بکاپ‌ها و رسانه‌های موجود حفظ شوند.
۵. پنل را باز کنید تا migration ۱۲، فقط جدول‌های `tg_*` با پیشوند فعلی DB را اضافه کند. اجرای چندباره امن است؛ جدول قدیمی حذف یا بازسازی نمی‌شود. برای نصب موجود هرگز نصب‌کننده اولیه یا ساخت دوباره کلیدها را اجرا نکنید.

## نصب تازه در cPanel

از File Manager پوشه `divan` را در public_html استخراج کنید. از MySQL Database Wizard دیتابیس و کاربر بسازید و دسترسی لازم بدهید. با HTTPS، مسیر `/divan/install/` را باز کنید و مراحل نصب موجود را انجام دهید. آدرس مبنا باید دقیقاً آدرس HTTPS همان محیط باشد. این کار فقط برای نصب خالی است، نه برای سرور فعلی.

PHP حداقل ۷٫۴ مطابق Backend؛ PHP ۸٫۳ برای این نسخه تست شده است. افزونه‌های PDO MySQL، OpenSSL، mbstring، cURL، JSON، fileinfo و zlib لازم‌اند؛ GD برای تصویر و DOM برای SEO. MySQL/MariaDB باید InnoDB و GET_LOCK را پشتیبانی کند. برای MP4 سقف upload_max_filesize حداقل 16M و post_max_size حداقل 20M باشد. مسیر PHP در Cron باید همان نسخه وب باشد. نیازی به Node، Composer، Redis یا SSH روی هاست نیست.

HTTPS از مقدار واقعی وب‌سرور بررسی می‌شود. اگر TLS در reverse proxy پایان می‌یابد، مدیر هاست باید HTTPS را فقط از پروکسی مورد اعتماد به PHP منتقل کند؛ هدر دلخواه کاربر قابل اعتماد نیست.

## ساخت ربات و تنظیم از پنل

۱. در حساب رسمی `@BotFather`، `/newbot` را اجرا و توکن دریافت کنید. توکن را فقط در پنل خودتان وارد کنید؛ در چت پشتیبانی، PR یا فایل عمومی قرار ندهید.
۲. با حساب Owner وارد پنل وب شوید؛ بخش «مدیریت تلگرام» را باز کنید. Bot Token را ثبت کنید. پس از ذخیره، فیلد خالی می‌ماند و توکن به مرورگر برنمی‌گردد. رمزنگاری با app_key موجود است؛ گم‌شدن این کلید، رمزگشایی را ناممکن می‌کند.
۳. مسیر Mini App برای این سرور: `https://httpuser87890.ir/divan/tg/app/`. برای staging، URL همان staging را وارد کنید. در این نسخه مسیر دیگری پذیرفته نمی‌شود.
۴. «آزمایش Telegram API» را بزنید. نتیجه getMe و زمان تماس را ببینید. موفقیت در محیط توسعه به معنی دسترسی هاست ایران نیست. تست روی هاست باید واقعاً موفق شود.
۵. ربات و مینی‌اپ را فعال کنید، فعلاً صف را متوقف نگه دارید. «ثبت Webhook امن» را بزنید؛ آدرس `/divan/tg/webhook.php` و secret سروری خودکار تنظیم می‌شوند. «وضعیت Webhook» باید خطا نداشته باشد. درخواست بدون secret عمداً 403 می‌گیرد.
۶. «تنظیم دکمه Mini App» منو و فرمان‌ها را تنظیم می‌کند. در صورت درخواست BotFather دامنه HTTPS همین محیط را معرفی کنید. برای انتشار به‌عنوان Main Mini App می‌توانید از تنظیمات BotFather همان URL را معرفی کنید؛ برای دکمه web_app خصوصی این مرحله اجباری نیست.
۷. حساب مدیر وب، شناسه عددی Telegram و نقش را انتخاب کنید. «ساخت پیوند اتصال» را بزنید و در همان حساب تلگرام، پیوند ۵ دقیقه‌ای را باز کنید. پیوند یک‌بارمصرف است و فقط برای شناسه عددی ثبت‌شده کار می‌کند. ابتدا تست ارتباط را انجام دهید تا نام ربات معلوم باشد و نیازی به تایپ فرمان اتصال نباشد.
۸. پس از اتصال، `/panel` را بزنید. ورود و تمام عملیات در مینی‌اپ بدون نام کاربری، رمز، TOTP یا تأیید امنیتی اضافی انجام می‌شوند. این رفتار مطابق درخواست صریح مالک است. هویت امضاشده تلگرام و مجوز هر درخواست همچنان در سرور بررسی می‌شود.

توکن نشست در sessionStorage است، در URL قرار نمی‌گیرد. تا زمانی که مینی‌اپ استفاده می‌شود، مهلت عدم فعالیت ۳۰ دقیقه‌ای بی‌صدا تمدید می‌شود. بعد از عدم فعالیت طولانی، بستن و بازکردن از دکمه ربات ورود تازه می‌سازد؛ رمز یا کد خواسته نمی‌شود. پس از لغو دسترسی، ورود خودکار نیز مسدود است. بازبودن حساب تلگرام مدیر، اختیار همان نقش را می‌دهد.

## Cron

در cPanel → Cron Jobs، هر دقیقه دستور زیر را با مسیر واقعی حساب و PHP انتخاب‌شده اجرا کنید:

```sh
/usr/local/bin/php /home/CPANEL_USER/public_html/divan/tg/worker.php
```

اگر هاست EasyApache دارد ممکن است مسیر PHP به شکل `/opt/cpanel/ea-php83/root/usr/bin/php` باشد. مسیر را از میزبان بگیرید. در Cron فیلدهای زمان را روی `* * * * *` قرار دهید؛ لازم نیست این پنج ستاره بخشی از Command باشند. اجرای worker از HTTP مسدود است. Cron قدیمی پرداخت/بکاپ را حذف نکنید؛ worker تلگرام جایگزین آن نیست.

GET_LOCK از اجرای هم‌زمان worker جلوگیری می‌کند. هر اجرا حداکثر ۲۰ پیام پردازش می‌کند. ثبت‌نام و پرداخت تماس شبکه‌ای به تلگرام ندارند. برای فعال‌سازی ارسال، توقف صف را بردارید و «پیام آزمایشی به خودم» را بزنید. این دکمه فقط به حساب متصل همان Owner پیام می‌دهد. Heartbeat و وضعیت صف را ببینید.

## آزمون staging و اتصال واقعی

ثبت‌نام آزمایشی در staging، رویداد یک‌باره و پیوند پروفایل را بررسی کنید. خرید آزمایشی را فقط در sandbox معتبر درگاه یا پاسخ آزمون انجام دهید. اتصال بازار و مایکت با حساب/خرید آزمایشی رسمی باید جداگانه بررسی شود؛ در این توسعه پول واقعی جابه‌جا نشده است. نقش Content نباید کاربران/فروش را ببیند، Support نباید Pro هدیه بدهد، Analyst نباید بنویسد. لغو مدیر در پنل باید بلافاصله نشست و پیام صف او را متوقف کند.

روی Telegram Android، iOS و Web، آپلود تصویر/GIF/MP4 مجاز، جایگاه‌های واقعی اپ، RTL، دانلود CSV خصوصی، قطع شبکه و بازشدن مجدد را بررسی کنید. آزمون مرورگر با Telegram SDK آزمایشی، جای آزمون در کلاینت واقعی و موبایل اقتصادی را نمی‌گیرد.

## وقتی Telegram API از هاست قابل دسترسی نیست

وضعیت خطاهای `telegram_http_*_curl_*` را در پنل ببینید؛ تنظیم secret و HTTPS به‌تنهایی محدودیت شبکه را حل نمی‌کند. این نسخه فقط اتصال مستقیم به `api.telegram.org` دارد. معماری جایگزین قابل بررسی: worker در یک میزبان با دسترسی Telegram، pull محدود از outbox با احراز هویت متقابل/HMAC، timestamp و nonce، allowlist مقصد/عملیات و ثبت ack. اعتبارسنجی webhook همچنان لازم است. این relay پیاده‌سازی یا آزمایش نشده؛ قبل از استفاده نیاز به توسعه، مدیریت کلید و آزمون دارد. توکن را به سرویس واسط ناشناس نسپارید.
