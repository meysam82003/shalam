## معماری

مرورگر → API مدیریتی با bearer کوتاه‌عمر → مجوز مستقل هر عملیات → سرویس دامنه مشترک → همان DB.
وبهوک → بررسی HTTPS و secret → ثبت یک‌باره update → فرمان خواندنی/پیوند مینی‌اپ → صف خروجی.
رویداد دامنه → outbox در همان transaction → fan-out مجاز → worker CLI cPanel → Telegram HTTPS.

کلید bot با AES-256-GCM و app_key فعلی ذخیره می‌شود؛ کلید Pro دست‌نخورده است. initData فقط برای یک exchange استفاده می‌شود؛ نشست مستقل با مهلت عدم فعالیت ۳۰ دقیقه‌ای، تمدید بی‌صدا هنگام استفاده و امکان لغو. طبق اصلاح صریح مالک ، عملیات پس از احراز هویت خودکار تلگرام فقط به مجوز نقش و دکمه اجرای اقدام نیاز دارند؛ هیچ رمز، TOTP یا تأیید امنیتی مجدد درخواست نمی‌شود. دلیل در Audit ثبت می‌شود. دسترسی به تلگرام بازِ مدیر معادل اختیار همان مدیر است. نقش تلگرام از سقف مجوز حساب وب فراتر نمی‌رود.

## حدود تحویل

اتصال واقعی تلگرام، اتصال هاست، نصب روی دیتابیس اصلی، تست دستگاه اقتصادی و تأیید مارکت واقعی نیازمند staging و تنظیم مالک‌اند. هیچ عدد نمونه در داشبورد production قرار نمی‌گیرد. وضعیت‌های پیاده‌سازی و تست در CHANGELOG و TEST-REPORT ثبت می‌شوند.
