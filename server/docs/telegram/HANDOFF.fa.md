# تحویل برای نصب توسط مالک — 1.0.0-rc3

## کدام فایل نصب می‌شود؟

فقط محتوای پوشه `divan/`، Backend قابل نصب است. docs، SQL، patch و manifest را در webroot رها نکنید. ZIP را پس از استخراج حذف کنید. راهنمای کامل INSTALL.fa.md و بازگشت ROLLBACK.fa.md داخل بسته هستند.

## تفاوت ارتقا و نصب تازه

- نصب فعلی: ابتدا پشتیبان فایل و DB؛ بررسی اختلاف سورس هاست؛ حفظ `storage/config.php`، کلیدهای Pro و داده‌ها؛ جایگزینی فایل‌های لازم؛ migration خودکار افزایشی ۱۲. نصب‌کننده اولیه را روی نصب فعلی اجرا نکنید.
- نصب آزمایشی: مسیر `public_html/divan-tg-staging/divan/`، دیتابیس خالی مستقل و ربات تست مستقل؛ STAGING.fa.md مراحل کامل را دارد. این مسیر، فایل‌های SEO را نیز از سایت زنده جدا می‌کند.

## بعد از نصب

۱. با Owner فعلی وارد پنل وب شوید و «مدیریت تلگرام» را باز کنید.
۲. توکن را در فیلد امن ذخیره، اتصال API را آزمایش و Webhook و دکمه مینی‌اپ را از همان صفحه تنظیم کنید.
۳. شناسه عددی تلگرام و حساب Owner را متصل کنید؛ پیوند یک‌بارمصرف را لمس کنید. نیازی به تایپ کد نیست.
۴. Cron هر دقیقه روی `tg/worker.php` نصب همان محیط تنظیم شود. Cronهای قبلی حفظ شوند.
۵. ربات، مینی‌اپ و صف را فعال کنید؛ «بررسی آمادگی و اتصال» و پیام تست خصوصی به خودتان را اجرا کنید.
۶. آزمون پذیرش پایین را روی محیط آزمایشی انجام دهید. پس از آن درباره ارتقای سرور اصلی تصمیم بگیرید.

ورود و عملیات روزمره تلگرام بدون نام کاربری، رمز یا تأیید امنیتی مجدد است؛ امضای سرور و نقش مدیر پابرجاست. ورود اولیه وب و دسترسی مالک حذف نشده‌اند.

## آزمون پذیرش نصب

| آزمون روی نصب شما | نتیجه مورد انتظار |
|---|---|
| API، Webhook، Menu و Cron | بررسی پنل موفق، پیام تست دریافت شود |
| بازکردن از ربات | ورود خودکار حساب متصل و نمایش داده همان DB |
| کاربر تلگرام متصل‌نشده | رد دسترسی |
| لغو دسترسی مدیر | نشست و ارسال صف همان مدیر متوقف شود |
| ثبت‌نام مصنوعی در staging | یک اعلان؛ پروفایل صحیح |
| خرید آزمایشی معتبر | تنها پس از تأیید سرور، رویداد خرید؛ بدون پرداخت واقعی |
| Pro هدیه و تمدید آزمایشی | دوره مستقل؛ عدم تغییر خرید قبلی |
| تبلیغ و رسانه | محدودیت واقعی قالب/جایگاه و آپلود پابرجا |
| گزارش با نقش محدود | فقط بخش‌های مجاز؛ CSV و پیش‌نمایش صحیح |
| قطع اینترنت و اتصال دوباره | خطای قابل فهم؛ عدم اجرای دوباره اقدام |
| بازار، مایکت و API اپ قبلی | آزمون سازگاری روی staging موفق |

## مرزهای واقعی این تحویل

پاسخ تیکت در این نسخه «یادداشت داخلی» است؛ Backend و اپ فعلی مسیر تحویل پاسخ به کاربر ندارند. اعلان اپ همان polling رضایتی موجود است، نه Push لحظه‌ای. Search Console بدون OAuth آمار ندارد. تغییر خرید به paid، بازپرداخت دستی، انتقال مالکیت خرید، سقف دستگاه اختصاصی هر کاربر و relay تلگرام ارائه نشده‌اند. چاپ/PDF به پشتیبانی مرورگر بستگی دارد. این‌ها نباید قابلیت فعال تلقی شوند.

گزارش TEST-REPORT آزمون‌های انجام‌شده را از آزمون‌های هاست و کلاینت واقعی جدا می‌کند. این ZIP روی Production نصب نشده و ادعای تأیید Production ندارد.
