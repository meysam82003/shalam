# واسط امن پرداخت ایران (Payment Verification Gateway)

## ۱. چرا و چطور
سرور اصلی دیوان (هلند، `httpuser87890.ir`) به API مایکت نمی‌رسد (Timeout). واسط روی هاست ایران (`pay.httpuser87890.ir`) فقط یک کار می‌کند: درخواست امضاشدهٔ سرور هلند را می‌گیرد، از API رسمی مایکت یا کافه‌بازار می‌پرسد و پاسخ فروشگاه را امضاشده برمی‌گرداند.

```
اپ اندروید → سرور هلند ──(HTTPS + HMAC)──→ واسط ایران ──(HTTPS)──→ API مایکت / بازار
            ← تصمیم و ثبت خرید ←──(پاسخ امضاشده)── واسط ایران ←── پاسخ فروشگاه
```

- حساب‌ها، اشتراک‌ها، تاریخ انقضا، تراکنش‌ها و دیتابیس فقط در هلند می‌مانند. واسط دیتابیس ندارد.
- تصمیم دربارهٔ خرید (معتبر، ردشده، بازپرداخت‌شده، تکراری، متعلق به حساب دیگر) همچنان با همان کد قبلی سرور هلند گرفته می‌شود. فقط مسیر رسیدن به فروشگاه عوض شده است.
- برای هر فروشگاه جدا انتخاب می‌کنید که «مستقیم از هلند» برود یا «از راه واسط ایران».

## ۲. امنیت
| خطر | محافظت |
|---|---|
| جعل درخواست | امضای HMAC-SHA256 روی زمان، Nonce و هش بدنه با کلید مشترک ۲۵۶ بیتی |
| تکرار درخواست (Replay) | Nonce یک‌بارمصرف که با ساخت انحصاری فایل ثبت می‌شود (اتمیک)، و بازهٔ زمانی ±۵ دقیقه |
| جعل پاسخ در مسیر | پاسخ واسط هم امضا می‌شود و به Nonce همان درخواست گره خورده است. پاسخ بی‌امضا یا دست‌کاری‌شده کنار گذاشته می‌شود و خریدی تأیید نمی‌شود. |
| پراکسی باز / SSRF | از درخواست‌کننده هیچ URLی پذیرفته نمی‌شود. فقط ۷ عملیات ثابت وجود دارد و هر کدام به یک Endpoint رسمی ثابت می‌رود. مقصدها فقط `developer.myket.ir` و `pardakht.cafebazaar.ir` هستند. |
| ورودی مخرب | نام بسته و شناسهٔ محصول باید در فهرست مجاز config باشند. توکن خرید با الگوی سخت بررسی می‌شود (جلوی تزریق هدر و مسیر گرفته می‌شود). |
| دسترسی غیرمجاز | فهرست IP مجاز (پیش‌فرض فقط `190.2.143.208`)، فقط روش POST، سقف بدنه ۱۶ کیلوبایت، سقف ۱۲۰ درخواست در دقیقه |
| افشای اسرار | توکن مایکت و کلید بازار فقط در `config.php` خارج از پوشهٔ عمومی هاست ایران هستند. لاگ فقط زمان، IP، عملیات، نتیجه و ۱۰ نویسه از هش توکن را دارد. درخواست بدون امضا هیچ اطلاعاتی دریافت نمی‌کند. |
| SSL | بررسی گواهی همیشه روشن است (`VERIFYPEER` و `VERIFYHOST=2`)، فقط HTTPS پذیرفته می‌شود و Redirect دنبال نمی‌شود. HTTP ساده رد می‌شود (به HTTPS هدایت نمی‌شود). |
| رسید تکراری یا حساب دوم | مثل قبل: هر رسید فقط یک بار و فقط برای یک حساب ثبت می‌شود (کلید یکتا در دیتابیس). درخواست هم‌زمان هم فقط یک دوره اضافه می‌کند. |

## ۳. نصب روی هاست ایران (فقط با File Manager سی‌پنل)
فایل `Divan-Payment-Bridge-Iran.zip` دو پوشه دارد:

| پوشه در ZIP | کجا برود |
|---|---|
| `public_pay/` | **محتوای** آن (`index.php` و `.htaccess`) داخل Document Root زیردامنهٔ `pay.httpuser87890.ir` |
| `divan-bridge/` | خود پوشه در **پوشهٔ خانه** (`/home/نام‌کاربری/`)، بیرون از هر پوشهٔ عمومی |

مراحل:
1. در cPanel، بخش Domains (یا Subdomains)، Document Root زیردامنهٔ `pay` را ببینید. معمولاً `/home/USER/pay.httpuser87890.ir` یا `/home/USER/public_html/pay` است.
2. File Manager → پوشهٔ خانه (`/home/USER`) → Upload → فایل ZIP → Extract.
3. محتوای `public_pay` را به Document Root زیردامنه منتقل کنید. اگر در File Manager فایل `.htaccess` را نمی‌بینید، از Settings گزینهٔ «Show Hidden Files» را روشن کنید.
4. پوشهٔ `divan-bridge` باید مستقیم در `/home/USER/divan-bridge` باشد. `index.php` آن را در `/home/USER/divan-bridge` یا کنار Document Root پیدا می‌کند.
   - اگر جای دیگری گذاشتید، کنار `index.php` فایل `bridge-path.php` را با این محتوا بسازید: `<?php return '/home/USER/مسیر/divan-bridge';`
5. در `divan-bridge`، فایل `config.sample.php` را Copy کنید و نام نسخهٔ جدید را `config.php` بگذارید.
6. `config.php` را با Edit باز کنید:
   - `keys`: کلید مشترک (بخش ۴ همین راهنما).
   - `myket_access_token`: توکن API از پنل توسعه‌دهندگان مایکت.
   - `bazaar_api_secret`: کلید API پیشخوان بازار (اختیاری؛ فقط اگر بازار هم از راه واسط برود).
   - `allowed_ips`: پیش‌فرض `190.2.143.208`. اگر سرور هلند IP خروجی دیگری دارد، همان را بنویسید.
   - `skus`: شناسهٔ همهٔ محصولات. اگر پلن تازه ساختید، شناسه‌اش را اینجا اضافه کنید. صفحهٔ واسط در پنل اگر شناسه‌ای جا افتاده باشد هشدار می‌دهد.
7. Permissions: پوشهٔ `divan-bridge` روی 700 و `config.php` روی 600. پوشهٔ `data` باید برای PHP نوشتنی باشد.
8. نسخهٔ PHP زیردامنه حداقل ۷٫۴ باشد (MultiPHP Manager)، با افزونهٔ `curl`.
9. آزمایش: در مرورگر `https://pay.httpuser87890.ir/` را باز کنید. باید `{"ok":false,"error":"method_not_allowed"}` ببینید (یعنی نصب شده و فقط POST می‌پذیرد). اگر `not_installed` دیدید، مسیر `divan-bridge` یا `config.php` درست نیست.

## ۴. ساخت و ثبت کلید مشترک (بدون افشا)
1. در پنل دیوان (هلند) ← تنظیمات ← **واسط پرداخت ایران** ← «ساخت کلید تازه» (فقط مدیر اصلی).
2. کلید ۶۴ نویسه‌ای و شناسه‌اش (مثلاً `k2`) **فقط یک بار** نمایش داده می‌شود.
3. در `config.php` ایران داخل `keys` بنویسید: `'k2' => 'همان کلید',`
   - کلید را در تلگرام، ایمیل، GitHub یا عکس صفحه نگذارید. مستقیم از پنل Copy و در File Manager Paste کنید.
4. در پنل «فعال کردن کلید تازه» را بزنید. پنل با کلید تازه از واسط می‌پرسد و فقط اگر پاسخ درست بود آن را فعال می‌کند.

**تعویض دوره‌ای کلید:** همین چهار مرحله را تکرار کنید (کلید فعلی تا فعال شدن کلید تازه کار می‌کند). بعد کلید قبلی را از `config.php` پاک کنید.

## ۵. راه‌اندازی در پنل هلند
1. ZIP به‌روز دیوان (`Divan-Emtiaz-Web-Installer.zip`) را مثل همیشه روی همان پوشهٔ قبلی Extract کنید. پوشهٔ `storage` دست نخورد. **این نسخه هیچ تغییری در ساختار دیتابیس ندارد.**
2. پنل ← واسط پرداخت ایران ← «آزمایش واسط». باید این‌ها را ببینید:
   - نسخهٔ واسط
   - اختلاف ساعت کمتر از ۲ دقیقه
   - «کلید مایکت روی واسط: ثبت شده»
3. «آزمایش مایکت از راه واسط»: پیام «کلید مایکت پذیرفته شد».
4. مسیر مایکت را روی «از راه واسط ایران» بگذارید و ذخیره کنید. پنل فقط وقتی می‌پذیرد که واسط همان لحظه درست پاسخ بدهد.
5. بازار فعلاً از هلند در دسترس است. می‌توانید «مستقیم» بماند یا آن را هم به واسط ببرید.

## ۶. انتقال امن تنظیمات API
1. توکن مایکت را **مستقیم از پنل مایکت** در `config.php` ایران بگذارید (از هلند کپی نکنید).
2. آزمایش‌های بخش ۵ را انجام دهید و مسیر را به واسط ببرید.
3. یک خرید آزمایشی واقعی (بخش ۹) انجام دهید.
4. بعد از موفقیت، در پنل هلند ← بازار و مایکت، فیلد «توکن دسترسی API» مایکت را با یک «-» پاک کنید تا توکن فقط در ایران بماند.
5. بازگشت: توکن را دوباره در پنل هلند وارد کنید و مسیر را «مستقیم» کنید.

کلید **عمومی** RSA مایکت (که در اپ هم هست) محرمانه نیست. آن را در پنل هلند ← بازار و مایکت ← «کلید عمومی RSA» وارد کنید تا امضای رسیدها در هلند بررسی شود. این کلید با توکن API فرق دارد.

## ۷. پاسخ‌ها و خطاها
| آنچه رخ می‌دهد | نتیجه برای خرید |
|---|---|
| فروشگاه خرید را پرداخت‌شده می‌داند | «تأییدشده»، Pro فعال، محصول مصرفی بعد از ثبت مصرف می‌شود |
| مایکت یا بازار بازپرداخت اعلام کرده (purchaseState=1) | «بازپرداخت»، Pro داده نمی‌شود (یا اگر قبلاً داده شده، پس گرفته می‌شود) |
| رسید ناشناخته (404) یا لغوشده (purchaseState=2) | «ردشده» |
| امضای رسید جعلی | قبل از هر تماس با فروشگاه رد می‌شود |
| واسط، فروشگاه یا شبکه در دسترس نیست؛ Timeout؛ خطای 401 یا 403 فروشگاه | هرگز «تأییدشده» نمی‌شود. طبق سیاست قبلی برنامه، اگر امضای RSA رسید معتبر باشد «تأیید امضا (در انتظار API)» می‌شود و Cron آن را دوباره از فروشگاه می‌پرسد. اگر بعداً رد شد، Pro پس گرفته می‌شود. |
| کلید مشترک اشتباه، ساعت نادرست یا IP غیرمجاز | «خطای احراز هویت واسط» در صفحهٔ واسط و داشبورد |
| پاسخ دست‌کاری‌شده یا بی‌امضا | کنار گذاشته می‌شود و رخداد امنیتی ثبت می‌شود |

Cron روزانهٔ فعلی (`cron.php`) خریدهای در انتظار را از همان مسیر انتخاب‌شده دوباره بررسی می‌کند.

## ۸. بازگشت (Rollback) بدون حذف اطلاعات
- **فوری:** پنل ← واسط پرداخت ایران ← هر دو مسیر را «مستقیم» کنید. همه چیز مثل نسخهٔ ۵.۳.۰ کار می‌کند.
- **کامل در هلند:** فایل‌های ZIP نسخهٔ ۵.۳.۰ را روی همان پوشه Extract کنید. این به‌روزرسانی هیچ Migration دیتابیسی ندارد، پس داده‌ای عوض نمی‌شود. تنظیمات واسط در جدول تنظیمات می‌ماند و نسخهٔ قدیمی آن را نادیده می‌گیرد.
- **ایران:** `index.php` زیردامنه را Rename کنید (مثلاً `index.php.off`) تا واسط خاموش شود.

## ۹. چک‌لیست تست نهایی پرداخت واقعی
پیش‌نیاز مایکت: APK مایکت باید کلید RSA مایکت را داشته باشد. نسخهٔ منتشرشدهٔ ۵.۳.۰ آن را **ندارد** (بخش ۱۰).

- [ ] «آزمایش واسط» در پنل سبز است و اختلاف ساعت زیر ۲ دقیقه است.
- [ ] «آزمایش مایکت از راه واسط» و در صورت نیاز «آزمایش بازار» سبز است.
- [ ] خرید یک‌ماههٔ واقعی در نسخهٔ مایکت (با حساب آزمایشی و کم‌ترین مبلغ) ← در پنل، تراکنش «تأییدشده» با روش «store_api» ← Pro فعال ← می‌توان دوباره خرید کرد (محصول مصرف شده است).
- [ ] همان کار در نسخهٔ بازار.
- [ ] خرید دوم: تاریخ پایان دقیقاً به انتهای دورهٔ قبلی اضافه شود.
- [ ] پاک کردن اپ، نصب دوباره، ورود به حساب و «بازیابی خرید» ← بدون دورهٔ اضافه.
- [ ] بازپرداخت یک خرید از پنل فروشگاه ← بعد از Cron، تراکنش «بازپرداخت» و Pro پس گرفته شود.
- [ ] خاموش کردن موقت واسط (Rename `index.php`) و خرید ← تراکنش «تأیید امضا (در انتظار API)»؛ روشن کردن دوباره ← بعد از Cron «تأییدشده».
- [ ] لاگ ایران (`divan-bridge/data/logs/`) هیچ توکن یا کلیدی نداشته باشد.

## ۱۰. موضوع APK مایکت (نیازمند تأیید مالک)
- APK مایکت نسخهٔ ۵.۳.۰ پیش از Commit «Configure public Myket billing RSA key» ساخته شده و کلید RSA مایکت در آن خالی است. بنابراین در نسخهٔ مایکت دکمهٔ خرید پیام «پرداخت مایکت در این نسخه پیکربندی نشده است» می‌دهد.
- رفع آن تغییر Backend نیست؛ APK تازه (مثلاً ۵.۳.۱) لازم است.
- فایل‌های متأثر:
  - `app/build.gradle`: فقط شمارهٔ نسخه، چون کلید از قبل در آن هست.
  - `ScreenHome.kt`: برچسب نسخه.
- هیچ ساخت یا انتشاری بدون تأیید مالک انجام نمی‌شود.
